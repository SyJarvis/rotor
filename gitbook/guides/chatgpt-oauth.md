# ChatGPT OAuth 渠道

Rotor 的模型渠道支持两种认证方式：上游 API Key 和认证登录。认证登录目前仅支持 ChatGPT OAuth，使用浏览器授权和 PKCE 校验，通过手动回填完整回调 URL 完成授权。

## 认证与额度的边界

本页说明 Rotor 如何连接 **ChatGPT 上游渠道**。客户端登录 Rotor 是另一套授权流程：

| 范围 | 认证对象 | 额度与用途 |
| --- | --- | --- |
| ChatGPT OAuth 渠道 | 管理员为渠道授权的 ChatGPT 账号 | Rotor 使用该账号的上游访问凭证调用 ChatGPT 后端；上游额度由 ChatGPT 决定。 |
| Rotor 客户端 OAuth、网页对话和账号所属 API Key | Rotor 账号 | 三条调用链共同累计 Rotor 账号已用额度；API Key 自身的限制只约束经该 Key 发起的请求。 |

渠道登录不等于客户端登录 Rotor，也不会取消 Rotor 的账号权限和配额检查。客户端登录方式见[客户端网页登录授权](client-oauth.md)，账号与 Key 配额见[管理 API Key 与配额](api-keys.md)。

当前已实现浏览器授权、保存凭证、按需续期、模型目录探测、授权状态检查和 Responses 调用。**上游额度查询、刷新按钮和缓存尚未实现**；「检查授权」和「探测模型」都不会读取剩余额度。

当前渠道使用 Codex 客户端 OAuth 参数和 `chatgpt.com/backend-api/codex` 后端，由 Rotor 自己管理登录与令牌，不依赖本机 Codex 的登录文件或 App Server。

## 新增渠道

1. 在管理控制台打开「模型渠道」，点击「新增渠道」。
2. 填写名称，将「渠道认证」切换为「认证登录」。登录服务为 **ChatGPT OAuth**。
3. 在第 1 步点击「生成授权链接」。Rotor 后端创建临时授权会话，并展示 `https://auth.openai.com/oauth/authorize?...` 官方链接；点击链接会在新页面打开，也可以复制到浏览器。
4. 在官方页面完成 ChatGPT 登录和授权。浏览器地址栏随后跳转到 `http://localhost:1455/auth/callback?code=...&state=...`。
5. 复制地址栏中的**完整 URL**，粘贴到 Rotor 第 2 步的「完整回调 URL」，点击「解析 URL」。界面显示解析出的 `code`、`state` 和 `redirect_uri`，以及当前会话匹配结果。解析仅校验回调值，不交换访问凭证。
6. 确认解析结果后，在第 3 步点击「完成授权」。只有此时后端才向 OpenAI 交换凭证。界面显示「授权已完成，保存渠道后生效」后，可以主动点击「探测模型」填入账号模型目录，或手动填写模型 ID；确认模型和所需路由配置后，点击「保存渠道」。授权完成不会自动探测或覆盖已填写的模型。

回调地址固定为 `http://localhost:1455/auth/callback`，不能改成 Rotor 服务的 `8010` 端口或当前管理页面地址。Rotor 不启动本地 `1455` 端口监听器；即使回调页面显示无法连接，也请复制地址栏里的完整 URL 回填。不要复制网页内容、浏览器 Cookie 或网页 session 信息。

回调中的 `state` 必须匹配当前授权链接，主机、端口和路径也必须符合固定回调地址。解析失败时「完成授权」不可点击；修改粘贴内容会清空解析预览，必须重新解析。会话过期或授权失败时，重新生成链接并完成新一轮授权。

每个授权码只能用于一次兑换。「完成授权」后若网络中断或结果无法确认，界面会禁用当前会话的再次兑换，必须生成新的授权链接；不能重复提交原回调 URL。解析步骤不进行兑换，URL 解析失败后可以修正输入并重新解析。

OAuth 渠道固定使用 `openai_codex` 服务商、`openai_responses` 协议和 `https://chatgpt.com/backend-api/codex` 地址。管理界面隐藏 API Key 和连接参数输入框。

Chat Completions 和 Anthropic Messages 入站请求会转换为 Responses，响应再转换回
客户端使用的协议。原生 Responses 请求沿用 Responses 语义，但不是字节级透传：
适配器强制 `store: false`、`stream: true`，移除 `temperature`，并应用渠道的模型名
映射；还会规范化文本输入和 `instructions`。客户端选择非流式响应时，Rotor 会收集
上游 SSE 后返回非流式结果。支持范围仍受下文的持久资源和后台请求限制。

「探测模型」读取当前 ChatGPT 账号的模型目录并保留上游标为隐藏的目录项；目录结果不代表生成验证，不会逐个发送生成请求，也不保证每个目录模型都能完成生成。新增渠道或重新登录后，探测使用尚未保存但已完成授权、未过期的临时会话；新会话仍在等待、兑换中、失败或过期时不能探测，也不会退回使用旧授权。探测只填写当前草稿，需要单独保存才生效；探测失败不清空模型。探测期间手动修改模型时，界面保留你的输入，可以再次点击探测获取目录结果。

## 编辑与重新登录

编辑已保存授权的 OAuth 渠道可以直接保存名称、模型、映射和路由配置，保留现有授权。点击「重新生成授权链接」会开始与当前渠道绑定的新会话；回填、解析并完成授权后再次保存渠道，才替换原凭证。未保存的新授权不会覆盖已保存的凭证。

没有新授权会话时，编辑窗口的「探测模型」使用渠道已保存的授权并填写草稿。渠道卡片菜单也提供「探测模型」；目录与现有配置不同时，确认后才更新模型列表，取消确认保留原配置。模型目录读取与「检查授权」是不同操作，都不代表模型生成实测。

关闭窗口、取消登录、切换认证方式或离开渠道页面会取消当前授权会话并清空回调预览。界面不会自动轮询或自动完成授权。保存失败时，已授权会话保留到其过期时间，可以修改配置后重试保存。

从 OAuth 切换到 API Key 时，必须填写新的上游 API Key。已有 OAuth 凭证不会当作 API Key 继续使用。

## 授权检查与请求限制

OAuth 渠道的卡片和编辑窗口显示相同的授权状态：

| 状态 | 含义与操作 |
| --- | --- |
| 未授权 | 没有完整的登录凭证，请登录 ChatGPT。 |
| 授权已保存 | 凭证已保存，尚未确认上游当前可用；可检查授权。 |
| 刷新暂时失败 | 刷新遇到网络超时、限流或服务异常，请重试检查；不代表登录失效。 |
| 需要重新登录 | 刷新凭证已失效或被明确拒绝，点击「重新登录」打开该渠道的编辑窗口，再生成授权链接。 |

访问凭证到期时间按浏览器本地时间显示。请求时会尝试自动续期，访问凭证到期或临近到期本身不代表需要重新登录。模型目录权限不足、生成参数错误和路由冷却也不代表授权失效。旧版本的未分类授权错误会保守显示为刷新暂时失败，先检查授权。

卡片菜单和编辑窗口的「检查授权」会检查服务端保存的凭证和有效期，并在临近到期时尝试刷新。检查成功或失败后，界面重新读取渠道的授权状态；同步失败时显示「授权状态未能同步」，可以重试，编辑中的名称和模型草稿会保留。「探测模型」使用已保存授权时也会同步授权状态，不会自动覆盖草稿。

结果「授权凭证已就绪（未验证上游）」不代表上游后端连通、模型生成成功或账户有特定模型的权限。未到刷新窗口的凭证可能只经过本地检查，已在 OpenAI 撤销的授权也可能在下一次请求或刷新时才被发现。未保存的新登录继续显示「授权已完成，保存渠道后生效」，不会被已保存渠道的检查结果覆盖。

第一版通过 Responses 的 HTTP/SSE 请求调用 ChatGPT 上游；不支持 WebSocket。`store: true`、后台任务、`previous_response_id`、`conversation` 以及依赖这些持久资源的操作不受支持，会返回明确的 4xx 错误。客户端应提供完整的当前请求上下文。

## 凭证与登录会话

浏览器接收官方授权链接、固定回调地址、授权状态和一次性会话 ID，并显示用户回填的授权码与 state。PKCE verifier、访问令牌和刷新令牌由 Rotor 后端持有，不通过渠道详情、表单附加 JSON 或保存请求传回浏览器。

新增或重新登录时，保存请求使用顶层 `auth_type: "oauth"` 和 `oauth_session_id`。后端将已授权会话的凭证与渠道保存一起处理；会话按管理员和目标渠道绑定，成功保存后不能再次用于另一个渠道。

渠道响应中的 `auth_status`、`auth_expires_at` 和 `auth_error` 是安全状态元数据，不是登录凭证。`auth_status` 分别使用 `unauthed`、`connected`、`temporary_error`、`reauth_required` 表达以上四种状态；API Key 渠道保持 `api_key`。界面不会根据错误文本或凭证到期时间猜测登录失效。

Rotor 临时登录会话从生成链接起有效 **15 分钟**，完成授权不会延长这个保存期限；这不是 OpenAI 授权码的有效期承诺。后端生成随机 `state` 和 PKCE verifier，授权链接使用 `S256` challenge，scope 为 `openid profile email offline_access`。完成授权时，后端将授权码、verifier 和固定回调地址发送到 `https://auth.openai.com/oauth/token`，取得访问令牌、刷新令牌和有效期，并从访问令牌中的账号字段提取 ChatGPT account ID。解析回调 URL 成功不等于这一步兑换成功。

成功保存后，凭证存入渠道，临时会话标记为已使用并清除其凭证；取消或过期处理也会清除临时会话秘密。访问令牌的到期时间来自上游返回的有效期，不是临时登录会话的 15 分钟期限。

续期是**按需触发**：生成请求、已保存渠道的模型探测和授权检查会调用同一个凭证解析入口。剩余有效期大于 5 分钟时通常直接使用已有令牌；进入提前刷新窗口时，后端用刷新令牌换取并保存新凭证。数据库租约和重新读取协调并发刷新，已保存的新登录会使旧刷新结果失效；没有定时后台续期任务。

已保存渠道的模型目录请求遇到 `401` 时，另有一次强制刷新后重查机制。目录重查仍返回 `401` 时，记录为需要重新登录；刷新过程中凭证被明确拒绝也会进入该状态。这个重查机制只适用于目录探测，当前生成请求不会在上游 `401` 后自动刷新并重发。目录地址为 `https://chatgpt.com/backend-api/codex/models`，当前使用 `client_version=0.161.0`；这是目录兼容参数，不是 Rotor 或 OpenAI SDK 的包版本。

## 上游额度查询（待实现）

目标是展示 ChatGPT 上游返回的额度快照，帮助管理员判断渠道是否接近限额。Rotor 本地请求记录、`usage_ledger` 和生成响应中的 `usage` 只记录经 Rotor 观察到的调用，无法推算 ChatGPT 账号在其他客户端的使用，也不能反推出上游总额度或剩余额度。查询结果应单独标为「上游额度」，不修改 Rotor 账号的 `quota`、`used_quota` 或 Key 限额。

### 已确认的能力与待验证的入口

官方 [Codex App Server 文档](https://learn.chatgpt.com/docs/app-server)区分两个 RPC：`account/rateLimits/read` 查询额度窗口；`account/usage/read` 查询 token 活动摘要和每日统计。额度 RPC 可以返回多个额度桶，以及窗口已用百分比、窗口时长和下次重置时间；套餐和 credits 信息只在服务返回时提供。Rotor 当前没有接入这些 RPC，它们也不是下面 HTTP 接口的返回约定。

针对当前 ChatGPT 后端接入，可先验证以下**候选请求**，凭证应由 Rotor 后端通过现有渠道获取，示例只含占位符：

```http
GET https://chatgpt.com/backend-api/wham/usage
Authorization: Bearer <access_token>
ChatGPT-Account-Id: <account_id>
Accept: application/json
```

本地 Codex `0.161.0` 客户端包含 `/wham/usage` 路径，可作为调查线索。本文未把该 HTTP 入口视为已验证、稳定的公开 API，也未使用 Rotor 已保存渠道进行实测。完整 URL、请求头要求、返回字段、账号覆盖范围和错误语义仍需确认；不能直接将官方 RPC 的字段名套到 HTTP JSON，也不能保证能查询所有 ChatGPT 网页模型的额度。

### 展示含义

| 数据 | 展示规则 |
| --- | --- |
| 额度桶与窗口 | 按上游实际返回的桶和窗口展示，不固定写成「5 小时」「7 天」，也不假设每个模型独享一份额度。 |
| 已用与剩余百分比 | 仅在已用百分比有效时展示；剩余百分比是该窗口的估算比例，不代表剩余 token 数或可调用次数。 |
| 重置时间 | 核对时间字段的单位后按本地时间展示；字段缺失时显示未知。 |
| 套餐与 credits | 有返回才展示；缺失、`null` 或无法识别都表示未知，不显示为余额 0 或额度充足。 |
| 查询时间与失败 | 显示快照获取时间。查询失败显示原因与未知状态；保留旧结果时明确标为旧快照，不当作当前额度。 |

授权有效、目录存在模型和上游额度充足是不同结论。即使额度查询成功且显示剩余，也不能代替一次实际模型生成验证。

### 后续最小实现与验收

先验证候选入口，再实现以下范围：

1. 后端复用渠道凭证解析和刷新入口查询额度，不向浏览器暴露访问令牌、刷新令牌或原始账号标识；管理 API 只返回经过校验的展示字段。
2. 渠道提供「上游额度」和手动刷新，设置短时缓存并返回快照时间。新授权保存后使旧快照失效；窗口和额度桶由结果决定。
3. 区分查询失败和登录失效。超时、限流、服务错误、权限不足或响应格式变化都不能直接判为需要重新登录；凭证刷新明确被拒绝时沿用现有授权状态。额度查询失败不清空渠道凭证，不修改本地账号配额。

完成标准是：用目标渠道做一次只读查询，确认请求和脱敏后的响应结构；模拟测试覆盖零使用、满额、多个窗口、字段缺失、无 credits、缓存过期与重新授权，以及网络、权限和认证失败。界面回归应验证未知值和旧快照提示，且刷新额度不会改动模型草稿或 Rotor 账号额度。上述验证尚未执行，不能据此声称候选入口已可用。

## 维护依据

本文的当前实现以 2026-10-10 的代码为准：`src/rotor/services/chatgpt_oauth.py` 负责登录、凭证刷新和模型目录，`src/rotor/adapters/providers/openai_codex.py` 负责上游 Responses 传输，`src/rotor/api/admin/channel_oauth.py` 和 `src/rotor/api/admin/channels.py` 提供管理操作。上游额度章节是后续设计，不是已有管理 API；实现或上游约定变化时应同步更新。
