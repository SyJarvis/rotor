## P0：已复现并修复（本次已上线）

### P0-1 `RemoteProtocolError: Server disconnected without sending a response`
- **现象**：`request_logs` 7 次失败，延迟 17–61s（`158432:61s / 158312:49s / 158377:34s`）；`request_attempts.error_code=upstream_connection_failed`。通道 `openai-pro/openai-plus`（`chatgpt.com`）、`command-goat`（`api.commandcode.ai`）、`opencode-go`（`opencode.ai`）。
- **根因**：
  1. 无单通道并发控制。`src/rotor/gateway/routing.py:218 admit_attempt` 只看 `enabled+cooldown`。实证：`16:11:30` 两路并行打同一 OAuth 账号（ch14），一路 14.4s 成功，一路 19s 被断连后 fallback ch9 又 15.8s 失败。
  2. 连接复用竞态。每个入请求一个 `AsyncClient(timeout=120.0)`，默认 `keepalive_expiry=5s`，同请求内 same-channel 重试复用坏连接。
  3. 同通道重试判定过窄。`src/rotor/gateway/fallback.py:15 is_connect_failure` 只认 `ConnectError/ConnectTimeout`，`RemoteProtocolError`（未收到响应、无计费、可安全重试）直接散到下一通道。
- **修复**（已构建 `rotor-new-rotor` 并重启，`/health 200`）：
  - `fallback.py`：`RemoteProtocolError` 视为 connect-class，可同通道 `0.5s/2.0s` 重试。
  - 新增 `src/rotor/core/http_client.py:create_upstream_client`（`Limits(max_keepalive_connections=0)`）；`api/v1/chat.py:180、responses.py:551、anthropic.py:821、embeddings.py:350、images.py:442` 改用。
  - `routing.py`：进程级 `max_in_flight`（`chatgpt.com/codex` 默认 1，`CHANNEL_MAX_IN_FLIGHT` 默认 4，`extra.max_in_flight` 可覆盖）；`config.py` 新增两项；`diagnose` 上报 `in_flight/in_flight_limit` 与 `concurrency_limit`。
- **验证**：容器内 `is_connect_failure(RemoteProtocolError)==True`，`codex limit=1/other=4`，满载阻塞、释放后恢复；未知 finish 仍 `UpstreamProtocolError`。

### P0-2 `UpstreamProtocolError: Invalid Chat stream finish reason: 'error'`
- **现象**：仅 `ch6 command-goat` + `google/gemini-3.8-flash`（唯一候选，无 fallback），10-25 起到 11-01 反复，延迟 7–36s，`error_code=upstream_invalid_response`，`fallback_allowed=False` 直接 502。
- **根因**：`api.commandcode.ai` 以 HTTP 200 + `choices[0].finish_reason="error"` 编码Provider 失败；`iter_chat_sse` 的 `reject_chat_error` 认不出（无 error 字段），`ChatStreamIntegrity.feed`（`openai_integrity.py:203`）直接 `_fail` 且丢弃 chunk 细节；`normalize_upstream_error` 对 `UpstreamProtocolError` 硬编码 `fallback_allowed=False`，流中炸还不记 cooldown。
- **修复**：
  - `openai_integrity.py`：`finish_reason=="error"` 时抽取 `choice/delta/message` 明细、`logger.warning` 打脱敏 chunk（前 2000 字符），抛 `UpstreamProtocolError("Invalid Chat stream finish reason 'error': <detail>")` 并置 `fallback_allowed=True, retry_same_channel=False`（类型不变，兼容 `test_unknown_or_empty_finish_never_becomes_chat_or_responses_success` 中 `finish="error"` 仍抛 `UpstreamProtocolError` 的断言）。
  - `exceptions.py:305`：`UpstreamProtocolError` 分支改为读取 `getattr(exc,"fallback_allowed"/"retry_same_channel",False)`，错误 finish  désormais 触发 `mark_failure`（30s cooldown）。
- **验证**：`finish="malformed_function_call"` 仍 `ProtocolError`；`finish="error"+content` 抛带明细的 `ProtocolError`，`should_fallback==True`。
