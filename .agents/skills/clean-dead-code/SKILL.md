# 冗余代码清理

系统性地识别并安全移除死代码。

## 核心原则

1. **grep 验证优于直觉** — 看起来"没人用"的东西可能被动态引用（字符串拼接、反射、配置映射）
2. **一次只删一类** — 每轮清理聚焦同一类冗余，便于 review 和回退
3. **跑测试兜底** — 删除后必须跑测试确认无破坏

## 清理类别与检查方法

按优先级从高到低执行，每类独立清理：

### 1. 死数据类 / 死配置类

被替代但未删除的旧模型、config 类。

```bash
# 确认类名无引用
grep -r "ClassName" src/ tests/ docs/ --include="*.py" -l
```

- 在 `src/` 内搜索定义处
- 在 `src/` + `tests/` + `docs/` 内搜索引用处
- 如果仅在 `__init__.py` 导出且无其他引用 → 移除定义 + 导出
- 如果有测试引用 → 先确认测试是否也是死代码

### 2. 未使用的导出

`__init__.py` 中导出但无外部消费的符号。

```bash
# 对每个导出名搜索外部引用
grep -r "SymbolName" src/ tests/ --include="*.py" -l | grep -v __init__
```

- 排除定义文件和 `__init__.py` 自身
- 无外部引用 → 从 `__init__.py` 移除导出行
- 定义本身也无其他引用 → 一并移除定义

### 3. 未使用的导入

工具自动检测：

```bash
ruff check --select F401,F811 src/
```

- F401：未使用的导入
- F811：重复导入

### 4. 未调用的函数 / 方法

```bash
# 搜索函数名（排除定义行）
grep -r "def func_name\|func_name(" src/ --include="*.py" -n
```

- 只有一行 `def func_name` → 无调用，可删
- 注意：可能被字符串拼接调用（如 `getattr(obj, method_name)`）
- 注意：可能作为回调参数传入（不在调用位出现函数名后跟 `(`）

### 5. 注释掉的代码块 / TODO 残留

- 大段注释掉的代码（>3行）→ 直接删除
- 过时 TODO（已解决或不再相关）→ 删除
- 保留有设计意图说明的注释

### 6. 空的 / 无操作的桩文件

- 只有 `pass` 或 `...` 的方法
- 空的 `__init__.py`（这是正常的，不删）
- 从未被继承的抽象基类

## 执行流程

```
1. 确定清理范围（单文件 / 单模块 / 整个 src/）
2. 按类别逐项检查（从上到下）
3. 对每项执行 grep 验证
4. 列出所有确认可删除的项，报告给用户
5. 用户确认后批量删除
6. 跑测试：pytest tests/ -x -q
7. 报告：删除了什么、节省了多少行
```

## 安全红线

以下情况**不删除**，即使 grep 显示无引用：

- `__init__.py` 中的 `__all__` 列表成员（可能被 `from pkg import *` 使用）
- 使用 `setattr` / `globals()` / `getattr` 动态访问的名称
- 注册到工厂/映射表的类（如 `ProviderFactory`、`ToolBackend`）
- Pydantic model / dataclass 字段（可能被序列化/反序列化使用）
- 测试中的 fixture 和辅助函数（可能被其他测试通过 conftest 引用）
- 文档中引用的代码示例

## 检查清单

- [ ] grep 验证每个待删符号无引用
- [ ] 检查动态引用可能性（getattr / setattr / 映射表注册）
- [ ] 同步移除 `__init__.py` 中的导出
- [ ] 同步移除关联的测试（如果测试只测试被删代码）
- [ ] 运行 `pytest tests/ -x -q` 确认无破坏
- [ ] 报告删除项列表和行数统计
